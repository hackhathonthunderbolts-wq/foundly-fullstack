# 8. Email-Based Relay / Connection

## 8.1 Principle
Users never see each other's raw email address until both explicitly opt in. All communication before that point flows through an **in-app relay thread** that is delivered to each user's real inbox as an email, but replies route back through the app/backend — similar to how marketplace apps (e.g., Airbnb, Facebook Marketplace) proxy contact.

## 8.2 Relay Thread screen (in-app)
- Header: shows the matched item's title + a small thumbnail from each post, plus the match confidence label ("Likely match").
- Message list: standard chat bubble UI, Foundly-neutral theme (not Lost/Found tinted, since this is a shared space between both parties).
- Composer: text input + attach-photo option (for extra proof photos, e.g., "here's a photo of the receipt").
- System messages inline in the thread: "Post matched automatically," "[Name] confirmed this is their item," etc.
- Actions in header overflow menu: **Confirm match**, **This isn't my item**, **Report user**, **Block user**.

## 8.3 Email relay mechanics
1. Each relay thread has a unique reply-to address generated by the backend (e.g., `thread-8f2c1a@relay.foundly.app`) that maps internally to the thread ID and both participants.
2. When User A sends a message in-app, it's stored in-app **and** optionally emailed to User B's real address from the relay address, with User A's name shown but not their raw email.
3. If User B replies directly from their email client (instead of opening the app), the reply is parsed at the relay address, matched to the thread by ID, and inserted back into the in-app thread — so the conversation stays usable from either side.
4. **Opt-in direct contact:** a "Share my email" button in the thread; only becomes fully mutual (both real addresses revealed to each other) once **both** users tap it. Until then, only the relay address is ever exposed.

## 8.4 Safety
- **Report user** flag routes to a lightweight moderation queue (visible to campus admin/support account) with the reported thread's content attached.
- **Block user** ends the relay thread and prevents future auto-matches between that pair of accounts.
- Rate-limit relay message sends per thread per minute to reduce spam/abuse potential.
